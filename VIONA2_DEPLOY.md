# VIONA 2.0 — запуск и ограничения

## Что входит в PR #53
- Новый редакционный дизайн главной страницы (контрастные поверхности, горизонтальная навигация, новые категории и художественные превью 7 товаров).
- Отдельные HTML-страницы для музыки, артиста, ботов, сайтов, кода, команды, поддержки и предварительных юридических разделов.
- Отдельная визуальная тема VIONA SoundLab и самостоятельная биография KANEKAN KAN.
- Запись музыкальных заявок (свой текст или оплата написания текста по отдельному согласованию) и откликов сотрудников в PostgreSQL. Google-админ-панель показывает эти заявки и позволяет менять их статусы.
- Тестовый Т-Банк: улучшенная обработка ошибок Init. При отказе банк НЕ считается подтверждённым; безопасный код ошибки виден клиенту.
- Предупреждение о юридических документах и согласие с ними в окне тестовой оплаты.

## Доменная схема
| Адрес | Действие |
|---|---|
| `viona.space` | Главный магазин |
| `soundlab.viona.space` | Самостоятельная музыкальная студия |
| `bots.viona.space` | Боты |
| `web.viona.space` | Сайты |
| `code.viona.space` | Разработка |
| `viona.space/KANEKANKANARTIST` | Сайт артиста |
| `viona.space/careers` | Отклики кандидатов |
| `viona.space/support` | Поддержка |

**Поддомены не начинают работать только от изменения кода.** Для каждого нового поддомена необходимо настроить Custom Domain в Render и CNAME у регистратора домена. Владелец должен брать точное значение CNAME и при необходимости TXT для проверки из Render → Service → Settings → Custom Domains. При корректном подключении Render оформляет HTTPS. Не заменять уже работающие DNS-записи основного домена.

Для предварительной проверки на уже подключённом `viona.space` есть алиасы `/music`, `/bots`, `/web`, `/code`.

**Временное ограничение:** ссылки из основного магазина на профессиональные поддомены будут работать только после DNS и TLS. Если поддомены не подключены, проверяйте страницы через указанные алиасы.

## База данных
Подключённая переменная `DATABASE_URL` обязательна. Новая миграция `022_viona2_requests.sql` создаёт `viona_music_requests` и `viona_career_applications`. Схема инициализируется при старте приложения вместе с существующими миграциями. Если возникнет ошибка миграции, приложение не должно выдавать ложное подтверждение сохранения заявки.

Google-админ-панель использует `GOOGLE_CLIENT_ID`, подтверждение Google-учётной записи и HTTPS cookie. Не вводите пароль Google в VIONA.

## Что не реализовано и не должно обещаться как готовое
- **Нет автоматического аудиогенератора:** SoundLab — форма на индивидуальную творческую услугу. Артист вручную согласует стоимость и объём работы. Поле «Написать текст» представляет платное дополнительное предложение, цена не взимается автоматически.
- **Нет коммерческого эквайринга:** платежи в магазине остаются DEMO. Музыкальная заявка вообще не инициирует списание. Юридические тексты — предварительные и требуют настоящих данных исполнителя, проверки правил возврата и обработки персональных данных до реальных оплат.
- **Нет авторизованного кабинета по музыкальным заявкам:** после сохранения выдаётся номер заявки; пока клиент уточняет статус через поддержку. Доступ к статусам и данным есть в Google-админке. Для безопасного персонального отслеживания на поддомене понадобится отдельно продуманный механизм входа.
- **Нет гарантий исправления банковской 502 без ответа банка:** код HTTP 502 в старой версии формировался когда Init вернул `Success=false`, не вернул `PaymentId` или вернул неподходящий PaymentURL. В новой версии API отдаёт поля `code` и `bankCode`, а в Render Logs есть безопасный `Demo payment Init bank response`. Секреты терминала не логируются и не должны отправляться в чат.
- **Нет автоматической оплаты и возврата** музыкальных услуг. Действительные договоры и реквизиты появятся только после законного оформления сервиса.
- **Биография артиста** предназначена для предварительной редакторской проверки. Не публикуйте личные медицинские или травматические сведения без осознанного решения владельца.

## Как проверить перед объединением
1. Убедиться, что GitHub Actions зелёный.
2. Открыть `/music`, `/KANEKANKANARTIST`, `/careers`, `/bots`, `/web`, `/code` и проверить обе мобильные ширины.
3. На тестовой базе отправить музыкальную заявку и отклик сотрудника, убедиться в ответе HTTP 201.
4. Войти в `/admin-console` с разрешённой Google-учётной записью и проверить вкладки **SoundLab** и **Команда**.
5. Проверить тестовую оплату. При 502 посмотреть `code`, `bankCode` и безопасные серверные логи, затем согласовать необходимые настройки с поддержкой Т-Банка.
6. Проверить юридические ссылки и работу согласия в тестовом оформлении заказа.
7. Утвердить публичную биографию и юридические тексты.
8. Настроить DNS/TLS и подтвердить открытие профессиональных поддоменов только после тестирования.

Main не должен объединяться до подтверждения владельца.
