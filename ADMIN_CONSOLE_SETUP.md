# VIONA — защищённая панель заказов (Т-Банк DEMO)

## Назначение
Отдельная страница `/admin-console` (не отображается в меню магазина и не индексируется поисковиками). Сам URL не даёт доступ к заказам. Для входа используется **Google Sign-In**: сервер проверяет подпись ID-токена, аудиторию, подтверждённый email и точное совпадение адреса администратора. Пароль Gmail никогда не вводится в VIONA и не хранится в GitHub.

## Настройка владельцем в Render
1. В Google Cloud создать OAuth Client ID типа **Web application** для своего проекта (при необходимости — вместе со взрослым, который юридически администрирует сервис). В Authorized JavaScript origins указать `https://viona.space` и отдельно домен предпросмотра, если нужен.
2. В Render → Environment добавить **GOOGLE_CLIENT_ID** с полученным Web Client ID. Подключить действующий PostgreSQL через **DATABASE_URL**, уже используемый VIONA. **PUBLIC_BASE_URL** должен соответствовать внешнему HTTPS-сайту.
3. Не добавлять Gmail-пароль или банковские пароли в репозиторий. `TBANK_DEMO_TERMINAL` и `TBANK_DEMO_PASSWORD` остаются только в защищённых переменных Render.
4. После деплоя открыть `https://viona.space/admin-console`, нажать «Войти через Google» и выбрать разрешённую учётную запись. Любой другой Gmail получит отказ независимо от знания URL.
5. Для проверки зайти обычным клиентом через Telegram, оформить тестовый заказ с DEMO-терминалом, оплатить **тестовыми** данными банка, дождаться статуса `CONFIRMED`. В админке изменить этапы, прикрепить файл кода до 1 МиБ и завершить заказ. Клиент увидит защищённую ссылку скачивания в своём заказе.

## Этапы
- `awaiting_payment` — ожидание подтверждения банка
- `queued` — заявка принята (только после банковского `CONFIRMED`)
- `in_progress` — в разработке
- `ready` — подготовка к отправке
- `completed` — готово (требует загруженного файла)

Дальнейшие этапы меняются **только** через защищённую админ-панель; старые Telegram-админ-методы отключены. Файлы доступны только клиенту, который оформил заказ через свой Telegram ID, **после** статуса `completed` и только при подтверждённой тестовой оплате.

## Ограничения
- Это демонстрационные платежи Т-Банка, не реальные списания и не работающий без настройки производственный эквайринг.
- Нужны PostgreSQL, тестовый банковский терминал и Google OAuth Client ID. Без них панель не сможет авторизоваться, хранить заказы и выдавать файлы.
- Панель скрыта из меню и снабжена `noindex`. «Спрятанный URL» не является мерой защиты — безопасность обеспечивается проверкой Google и серверными разрешениями.
- Уже опубликованный пароль, если он действующий, необходимо заменить в Google-аккаунте и проверить двухэтапную аутентификацию.
